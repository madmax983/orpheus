# 🔭 Vantage: Spec for Audio-rate Pattern Control

## 👤 User Story
"As a Sound Designer, I want to modulate voice parameters at audio-rates (like FM synthesis or fast filter sweeps) directly from my patterns, so that I can create complex, evolving timbres without writing custom DSP graphs for every sound."

## ❓ The "So What?" (Business Problem)
Currently, pattern control data (p1-p4) is interpolated per-frame (breakpoint-rate). While this is great for automation, it prevents true audio-rate modulation (like audio-rate FM or AM), which is a staple of modern electronic music. If we can't do this from the pattern layer, users are forced into the Faust-style DSP graph DSL, increasing friction during a live set. By bridging patterns to audio-rate control, we maximize utility and keep the user in the fast, intuitive pattern language.

## 🎯 Metric Definition
- **Success** = Pattern evaluation can emit audio-rate buffers for p1-p4, which the voice graph consumes at sample rate without artifacts, introducing <10% additional CPU overhead per voice.

## 🔍 Gap Analysis
- **Current State:** The roadmap says "literal audio-rate pattern evaluation is beyond Tidal parity and intentionally out of scope". We currently do breakpoint-rate per-frame interpolation.
- **The Gap:** We need a way to pass continuous signals or high-rate control data generated by patterns down to the voice without evaluating the pattern *at* the audio rate. We can do this by having the pattern emit a signal definition (e.g., an LFO rate/depth) that the DSP engine instantiates, rather than calculating every sample in the language layer.

## ✅ Acceptance Criteria
- Must allow assigning an LFO or fast envelope generator to p1-p4 from the pattern language (e.g., `p1(lfo(400))`).
- Must instantiate the control signal generator on the DSP audio thread for sample-accurate, audio-rate modulation.
- Must not attempt to evaluate the entire pattern tree at the audio rate.
- Must seamlessly integrate with the existing `p1`..`p4` trailing signal inputs on `GraphVoiceSpec`.

## 🚫 Out of Scope
- Evaluating the entire Tidal-style AST at sample-rate.
- Custom arbitrary DSP math inside the pattern layer (that remains the job of `graph { }`).
